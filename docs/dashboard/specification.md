# 🚀 Cassandra Framework
## Техническое задание: Страница Dashboard (Загрузка системы)

### 📌 Обозначения
-   **`ElementName`** *(type)* — UI-элемент с указанием типа
-   *"Text content"* — отображаемый текст на интерфейсе
-   `code` — технические термины, классы, методы
-   `'/dashboard.html'` *(url)* — адрес страницы (URL) для проверки навигации
-   ⚠️ *(decorative)* — декоративный элемент, не подлежит автоматизированному тестированию

## 1. 🎯 Назначение
Центральный экран управления системой оценки колонизации. Обеспечивает отображение данных авторизованного пользователя, последовательную визуальную инициализацию (загрузку) модулей системы по команде `Uplink`, навигацию по основным разделам и безопасный разрыв сессии (выход из системы).

## 2. 🖥️ Элементы интерфейса

### 2.1 Информационные панели (Info Circles)

- **`Role Panel`**  *(info-circle)* — Панель роли пользователя (верхний левый угол). Содержит:

    - **`Role Icon`** *(emoji)* — Иконка роли.

    - **`Role Label`** *(text)* — Название роли.

    - **`Role Tooltip`** *(tooltip)* — Всплывающая подсказка при наведении.

- **`User Panel`** *(info-circle)* — Панель пользователя (верхний правый угол). Содержит:

    - **`User Icon`** *(emoji)* — Иконка астронавта.

    - **`User Label`** *(text)* — Позывной пользователя.

    - **`Status Dot`** *(decorative)* — Индикатор статуса.

    - **`User Tooltip`** *(tooltip)* — Всплывающая подсказка.

### 2.2 Декоративные элементы ⚠️

> **Примечание:** Элементы данного раздела являются частью визуального оформления страницы и **не подлежат автоматизированному тестированию**. Они не имеют `data-wm-id` и не включаются в CAS-сценарии.

-   **`Cassandra Logo`** ⚠️ (decorative/text) — Заголовок "CASSANDRA" в центре.

-   **`Stars Background`** *(decorative/css)* — Анимированный фон со звёздами и Млечным Путём.

### 2.3 Основные элементы управления

- **`Uplink Button`** (button) — Кнопка инициализации системы (нижний правый угол). Label: `"Uplink"`. Иконка: `📡`.
Состояние по умолчанию: Активна, имеет анимацию пульсации (uplink-active).
Состояние после 100% загрузки: Неактивна, теряет пульсацию, становится серой (grayscale) и полупрозрачной (opacity: 0.5).

- **`Logout Button`** (button) — Кнопка разрыва связи / выхода из системы (нижний левый угол). Label: `"Logout"`. Иконка: `🌑`. Изначально скрыта (uplink-hidden).
Поведение при наведении: В состоянии panel-online кнопка увеличивается (scale(1.15)) и усиливает неоновое свечение — симметрично с центральными навигационными кнопками.

- `Planet Bar` (button-group) — Контейнер с 5 центральными навигационными кнопками. Изначально скрыты (uplink-hidden). Все кнопки имеют эффект увеличения при наведении в активном состоянии:

    - **`Galaxy Map Btn`** (button) — Label: `"Galaxy Map"`. Иконка: `🌌`.

    - **`Flight Calc Btn`** (button) — Label: `"FLIGHT CALC"`. Иконка: `💫`.

    - **`CIS Table Btn`** (button) — Label: `"CIS INDEX TABLE"`. Иконка: `🧬`.

    - **`Mission Control Btn`** (button) — Label: `"MISSION CONTROL"`. Иконка: `🚀`.

    - **`Settings Btn`** (button) — Label: `"Cassandra Settings"`. Иконка: `⚙️`.

### 2.4 Служебные элементы

- **`Uplink Progress Container`** (decorative/container) — Контейнер прогресс-бара загрузки. Изначально скрыт. Содержит Progress Track, Progress Fill и Progress Text.

-   **`Telemetry`** *(text)* — Строка состояния системы в футере. Отображается моноширинным шрифтом с мигающим курсором (`█`). 

    - **Важно** (Tone of Voice): Весь текст выводится от лица системного ИИ CASSANDRA и всегда начинается с префикса > CASSANDRA: (в коде стилизован как > CASSAN #ffffff + DRA #4da6ff).

    -   Состояние по умолчанию (до uplink): *"> {FULL_NAME}, SERVER CONNECTION REQUIRED. INITIALIZE UPLINK PROCEDURE."* (синий цвет, rgb(77, 166, 255) / #4da6ff).

    -   Состояние после (после uplink): *"> {FULL_NAME}, SYSTEM READY FOR WORK. AWAITING COMMANDS."* (зелёный цвет,rgb(46, 204, 113) / #2ecc71).

## 3. ✅ Правила состояний (State Rules)

- **Состояние `panel-offline`** 

    - Применяется к информационным панелям при загрузке, а также к кнопкам (Logout, Planet Bar) в момент их появления во время загрузки.

    - Визуально: Элементы выглядят цветными, с неоновым свечением (не серые и не тусклые).

    - Интерактивно: Полностью заблокированы для мыши (pointer-events: none, cursor: default).

    - Тултипы скрыты (display: none), клики и наведения (hover) не срабатывают.

- **Состояние `panel-online`**

    - Применяется ко всем вышеуказанным элементам после достижения прогресса 100%. Элементы приобретают полную интерактивность (pointer-events: auto), тултипы становятся доступны, срабатывают hover-эффекты.

    - Состояние uplink-hidden / uplink-visible: Управляет видимостью центральных и нижних кнопок. Переход сопровождается пружинистой анимацией (cubic-bezier).

## 4. ⚙️ Логика работы

> ⚠️ **Важно: Контекст проекта**
> Проект не имеет серверной части. Данные пользователя читаются исключительно из localStorage (ключ currentUser).

- **Инициализация `initDashboard`**

    - При загрузке DOM скрипт проверяет наличие currentUser в localStorage.

    - Если данных нет или они повреждены: текст Telemetry становится красным, через 1.5 сек происходит редирект на login.html.

    - Если данные валидны: скрипт динамически подставляет данные в Role Panel и User Panel. Запускается эффект печатной машинки в Telemetry.

- **Процедура Uplink `startUplink`**

    - По клику на Uplink Button кнопка деактивируется. Появляется Uplink Progress Container, запускается асинхронная последовательность:

        - `10%`:Появляется `Logout Button` (в состоянии panel-offline).

        - `22%`: Текст в телеметрии: `"LOADING CENTRAL MENU CONTROL"`.

        - `36% - 95%`: Поэтапное появление кнопок `Planet Bar` (в состоянии panel-offline).

        - `99%`: Текст в телеметрии: `"SYNCHRONIZING WITH CORE"`.

        - `100%`:Все кнопки (Logout, Planet Bar) и панели переключаются из panel-offline в panel-online.
        Кнопка Uplink Button теряет класс пульсации, становится серой (grayscale(100%)) и полупрозрачно (opacity: 0.5).Прогресс-бар плавно исчезает.
        
        - Текст телеметрии становится зеленым: `"{CALLSIGN}, SYSTEM READY FOR WORK. AWAITING COMMANDS."`

    - **Процедура выхода `handleLogout`**

        - По клику на Logout Button вызывается функция handleLogout().

        - Из localStorage удаляется ключ currentUser.

        - Происходит мгновенный редирект на login.html.

- **Local Base URL (Локальная разработка и тесты):** 
  - Главная: `file:///.../cassandra/index.html`
  - Дашборд: `file:///.../cassandra/dashboard.html`

- **GitHub Pages URL (Публичный деплой):** 
  - Главная: `https://<username>.github.io/cassandra/`
  - Авторизация: `https://<username>.github.io/cassandra/login.html`
  *(Остальные страницы формируются аналогично, с обязательным суффиксом `.html`)*

> **Примечание для автоматизации:** 
> В конфигурационных файлах фреймворка (например, `config.py`) определяется базовый URL (`BASE_URL`) в зависимости от окружения. 
> Переход на конкретную страницу осуществляется путем добавления имени файла (например, `login.html`) к `BASE_URL`. Это гарантирует корректную работу тестов как на локальной машине, так и в CI/CD.
