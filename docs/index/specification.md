# 🚀 Cassandra Framework
## Техническое задание: Страница Index (Главная / Точка входа)

### 📌 Обозначения

-   **`ElementName`** *(type)* — UI-элемент с указанием типа
-   *"Text content"* — отображаемый текст на интерфейсе
-   `code` — технические термины, классы, методы
- `'/index.html'` *(url)* — адрес страницы (URL) для проверки навигации
-   ⚠️ *(decorative)* — декоративный элемент, не подлежит автоматизированному тестированию

## 1. 🎯 Назначение
Главная страница — стартовая точка входа в систему оценки колонизации. Обеспечивает первичное визуальное знакомство пользователя с проектом, демонстрацию фирменного стиля (анимация ЭКГ, космический фон, типографика) и предоставляет навигацию к точкам входа: авторизации `Log in`, и регистрации нового пользователя `Sign Up`.

## 4. ⚙️ Логика работы

⚠️ **Важно: Контекст проекта**
> Главная страница (index.html) является точкой входа. При загрузке страницы выполняется проверка наличия активной сессии (currentUser в sessionStorage).

- **Инициализация страницы**

    - При загрузке DOM скрипт проверяет sessionStorage.getItem('currentUser').

    - Если сессия существует: Происходит мгновенный редирект на dashboard.html. Пользователь не видит элементы главной страницы.

    - Редирект срабатывает для любого валидного пользователя в сессии, независимо от его происхождения: будь то `AURORA`/`ORION` (предсуществующие),  `NOVA` (зарегистрированный через signup.html) или `KNOPA` (восстановленный через access-restoration.html).

    - Для системы важна только факт наличия валидного JSON в `sessionStorage` 

    - Если сессии нет: Пользователь остаётся на index.html, отображаются все элементы согласно CSS.

- **Навигация**

    - Клик по `Log in Button` → мгновенный переход на `login.html`.

    - Клик по `Sign Up Button` → мгновенный переход на `signup.html`.

    - Клик по `Restore Button` → мгновенный переход на `access-restoration.html`.

## 7. 🎨 Визуальные требования

- **Цветовая схема:** Тёмно-синий космический фон #050816, голубые акценты #4da6ff, белый текст #ffffff, приглушённый текст #8a94b8 (заголовок) и #6a7498 (слоган), футер #5a6488.

- **Анимации:**

    - Плавное рисование линий ЭКГ (`drawHeartbeat`, `15s`, `linear`, `infinite`).

    - Плавный переход кнопок при наведении (`transition: all 0.3s ease`).

- **Адаптивность:**

    - Адаптивность: `Desktop-only` (1024px+). Мобильная версия не предусмотрена.

> Все интерактивные элементы должны иметь уникальный атрибут `data-wm-id` для надёжной автоматизации.

## 9. 🌐 URL и маршрутизация
Так как проект является учебным и статическим (без серверной части), для локальной разработки и деплоя на GitHub Pages используются следующие адреса:

- **Local Base URL (Локальная разработка и тесты):**
    - Главная: `file:///.../cassandra/index.html`
    - Авторизация: `file:///.../cassandra/login.html`
    - Регистрация: `file:///.../cassandra/signup.html`
    - Восстановление: `file:///.../cassandra/access-restoration.html`

- **GitHub Pages URL (Публичный деплой):
    - Главная: `https://<username>.github.io/cassandra/index.html`
    - Авторизация: `https://<username>.github.io/cassandra/login.html`
    - Регистрация: `https://<username>.github.io/cassandra/signup.html`
    - Восстановление: `https://<username>.github.io/cassandra/access-restoration.html`

- *(Остальные страницы формируются аналогично, с обязательным суффиксом `.html`)*

> **Примечание для автоматизации:** 
>В конфигурационных файлах фреймворка (например, `config.py`) определяется базовый URL (`BASE_URL`) в зависимости от окружения.
>Переход на конкретную страницу осуществляется путем добавления имени файла (например, `index.html`) к `BASE_URL`. Тесты для главной страницы не требуют предварительной настройки sessionStorage и должны запускаться с чистым профилем браузера.
